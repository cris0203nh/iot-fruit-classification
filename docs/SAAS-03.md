# SaaS-03 — organizaciones y aislamiento

- Alembic `s003organizations`: crea `organizations` y `organization_memberships`; organización **AgroScan Inicial**. Conserva `users`, `user_roles`, IDs y columnas históricas; migra cada asignación de rol como membresía, admitiendo varias organizaciones y roles existentes por usuario. Una identidad sin roles conserva su ausencia de permisos.
- Añade organización obligatoria a 14 tablas operativas, FK compuestas e índices por organización y recurso. Las relaciones indirectas también deben compartir lote/evaluación/imagen. Códigos de lote únicos por organización, sin distinguir mayúsculas ASCII como SQLite `lower()`; secuencias IoT únicas por organización/dispositivo/arranque.
- Login conservado. `GET /api/auth/organizations` lista únicamente membresías activas propias. `X-Organization-ID` se valida contra membresía y organización activas en cada solicitud; sin cabecera solo se resuelve una membresía empresarial inequívoca. Sin membresía: 403; varias organizaciones sin selección: 409. Nunca se usa una organización global por defecto.
- Contexto obligatorio en todas las rutas operativas; filtros ORM para consultas, cargas de relaciones y actualizaciones masivas, asignación empresarial de nuevas filas y autorización previa de IDs de ruta. `GET /api/auth/me` conserva su respuesta y añade `organizationId`; roles efectivos provienen de las membresías. Gestión de usuarios limitada a la organización activa: desactivar o cambiar rol afecta membresías, no cuentas compartidas en otras organizaciones.
- **53 operaciones HTTP protegidas**, incluidas consultas, escrituras, fotografías, revisiones, historial, reportes y resultados de visión. Se comprueban **36 operaciones con IDs ajenos en ruta**, además de identificadores en cuerpos, códigos repetidos, relaciones SQLite, permisos por empresa y solicitudes simultáneas.
- IoT (`/api/iot/measurements`, `/api/iot/status`) y respaldos globales (`/api/admin/backups`, `/restore`) devuelven **503 para todos los clientes** hasta SaaS-07, antes de invocar servicios o crear archivos. El servicio de respaldo/restauración se conserva para mantenimiento aislado; no existe opción HTTP para eludir el bloqueo.
- Migración probada en copia consistente de la base existente: 17 tablas de datos conservan exactamente todas sus columnas y filas originales; dos asignaciones de rol migradas sin duplicación. Upgrade repetido, downgrade y nuevo upgrade verificados; FK e integridad correctas. Fotografías intactas. Respaldo/restauración posterior en WAL: 35 imágenes vinculadas y 86 archivos, SQL y SHA-256 idénticos.
- **109 pruebas backend y 8 de autenticación/sesión frontend aprobadas**; `git diff --check` correcto. Cubren organizaciones/migración SaaS-03, SQLite SaaS-02, seguridad e integridad AG-046, autorregistro, decisiones, usuarios, estado IoT y respaldo unitario/integración/API. Las fixtures ejecutadas incorporan la organización inicial; las expectativas HTTP de IoT/respaldos reflejan el bloqueo intencional. No se ejecutó la suite completa de IA; build/lint frontend no aplican porque no cambió su código.
- No se migró la base original ni se habilitó producción. La reversión rechaza organizaciones adicionales, relaciones inválidas o cambios de membresías que perderían permisos. Aplicar la migración original requiere mantenimiento autorizado y copia de seguridad; no restaurar por HTTP bases anteriores al esquema empresarial.

El frontend actual sigue funcionando para una organización; usuarios con varias deben seleccionar contexto mediante la API. Permanecen los límites de SQLite/proceso único descritos en SaaS-02.
